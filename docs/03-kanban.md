# Kanban do projeto

Vamos usar o Kanban para acompanhar o que cada pessoa está fazendo. Este arquivo organiza as tarefas iniciais. O quadro no GitHub Projects ainda precisa ser criado.

As colunas serão: **A fazer**, **Em andamento**, **Em revisão** e **Concluído**.

## Situação inicial

A documentação inicial está em revisão pelo grupo. As tarefas de implementação ainda estão a fazer. Não temos testes executados registrados.

## Tarefas

| ID | Tarefa | Responsável | Quando considerar pronta |
| --- | --- | --- | --- |
| 01 | Revisar os documentos e preencher os nomes | Todos | O grupo conferir o conteúdo e a divisão. |
| 02 | Confirmar os botões e a conexão USB com o professor | Grupo | Registrar a resposta recebida. |
| 03 | Ler os dois botões no Arduino | A | Identificar quando cada botão está apertado ou solto. |
| 04 | Executar o projeto do laboratório | B | Abrir a aplicação no computador do grupo. |
| 05 | Ligar os botões à movimentação do personagem | A e B | Mover e parar o personagem pelos botões. |
| 06 | Criar frutas, coleta e pontuação | B | Coletar e perder frutas sem duplicar a contagem. |
| 07 | Fazer menu, pausa e reinício | C | Conseguir usar todas essas opções pelo dispositivo. |
| 08 | Implementar as três fases | B e C | Conseguir jogar as três e perceber a progressão. |
| 09 | Integrar um indicador dos botões à pontuação | B e D | A regra estar explicada e funcionando. |
| 10 | Tratar problemas de conexão | A e B | Informar a falha e não manter comandos antigos. |
| 11 | Mostrar os resultados | C | Os números baterem com os eventos da partida. |
| 12 | Escrever o short paper | D, com revisão de todos | Texto dentro do limite e com prints reais. |
| 13 | Testar o projeto completo | Todos | Registrar os resultados e corrigir as falhas. |
| 14 | Gerar o executável | B | Abrir o jogo fora da IDE com as instruções. |
| 15 | Conferir e enviar a entrega | Todos | Código, executável e relatório conferidos. |

Os responsáveis são provisórios. Vamos trocar A, B, C e D pelos nomes reais.

## Como vamos atualizar

Ao começar uma tarefa, movemos para Em andamento. Quando houver algo para conferir, vai para Em revisão. Só marcamos como Concluído depois de verificar se funcionou e colocar o link do commit ou do resultado.

Em cada reunião, vamos mostrar o que foi feito, a participação de cada um, os problemas encontrados e o que faremos na próxima semana.
